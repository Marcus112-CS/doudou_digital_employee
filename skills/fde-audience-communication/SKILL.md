# 多对象沟通

输入为项目事实、沟通对象、本次目标、渠道和篇幅。优先确认“希望对方理解或决定什么”。已有对象和目标即可开始；未知细节不会影响表达时使用中性表述。

## 选择重点

| 对象 | 组织重点 | 推荐结构 |
|---|---|---|
| 客户业务人员 | 业务影响、价值、限制、需要配合的事项 | 现状 → 对业务意味着什么 → 下一步 |
| 客户技术人员 | 接口、数据、环境、证据、技术边界 | 问题 → 已核查内容 → 待验证条件 |
| 内部领导 | 结果、阻塞、影响、资源或决策请求 | 一句结论 → 关键进度 → 请求 |
| 内部协作人员 | 背景、明确问题、所需材料和帮助 | 简要背景 → 具体求助 → 资料与期望时间 |
| 产品/售前人员 | 需求证据、适配条件、能力边界 | 场景 → 需确认能力 → 可验证的问题 |

角色只是初始关注点，服从用户给出的真实沟通目的，不推断个人性格和偏好。

## 生成与核对

1. 提取本次必须传达的事实、风险和行动请求。证据不足的内容写为待确认；按用户要求的长度取舍细节。
2. 客户草稿使用允许对外表达的信息。内部联系人、资源安排、未公开价格和原始排查材料留在内部建议。重要风险需要披露但只有内部表述时，给 FDE 一个待确认的可公开措辞，不能悄悄省略风险。
3. 用熟悉的业务词解释术语，保留必要技术含义。收益、完成度、时间和承诺逐项与原资料核对。
4. 切换对象时沿用同一份事实，不因面向领导或客户而提高完成度或隐藏限制。期望时间使用“建议/希望”，已确认时间才写“已约定”。
5. 输出可用草稿，再给 FDE 必要的依据与待确认项。用户只需要短回复时不附长篇分析。文本草稿不会自动发送。

## 默认输出

**沟通草稿**：适配渠道和篇幅，可直接复制。
**内部提示**：依据、必要待确认项；与客户正文分开。

## 例子

共同事实：“8 台中 6 台采集成功，2 台因权限不足未完成；报告待客户验收。”

- 向领导：“已验证 6/8 台，剩余 2 台受权限阻塞；报告待验收。需要协调访问权限后安排复测。”
- 向客户：“已完成 6 台主机的数据采集验证，另外 2 台需补齐访问权限后继续验证。报告还需要与您确认验收结果。”

两段都保留范围和验收状态。不能写“项目已交付”或自加“今天全部完成”。
