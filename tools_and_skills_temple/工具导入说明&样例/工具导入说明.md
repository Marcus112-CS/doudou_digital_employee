# 工具导入说明

平台支持三种类型的工具导入：**API 工具**、**MCP 工具**、**MCP 脚本工具**。三种工具的导入文件要求不同，请按本文档准备对应的 ZIP 交换包。

---

## 1. 通用要求

无论哪种类型，导入文件都遵循以下共同规则：

| 项 | 要求 |
|---|---|
| 文件格式 | `.zip` 压缩包 |
| 文件大小 | ≤ 200 MB |
| 编码 | manifest JSON 使用 UTF-8 编码 |
| manifest 文件 | ZIP 根目录下**恰好一个** `.json` 文件，作为工具元数据声明 |
| 附带文件 | 除 manifest 外，仅 `mcp_script` 类型可附带一个脚本包 ZIP |

> **关键**：manifest JSON 必须位于 ZIP 的**根目录**，不要多套一层目录。打包后用解压软件查看，`manifest.json` 应直接出现在第一层。

### 1.1 manifest 通用字段

manifest JSON 顶层是一个对象，包含以下字段：

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `name` | 是 | string | 工具名称，不能为空 |
| `typ` | 是 | string | 工具类型：`api` / `mcp` / `mcp_script` |
| `industry` | 是 | string | 所属行业，不能为空 |
| `description` | 否 | string | 一句话描述 |
| `desc` | 否 | string | 详细描述 |
| `config` | 否 | object | 工具配置，结构随类型不同（见下文各类型章节） |
| `asset_label` | 否 | array | 资产标签 |

## 2. API 工具（`typ: api`）

通过 OpenAPI / Swagger schema 描述一组 HTTP 接口，平台据此生成可调用的子工具。

### 2.1 文件结构

```
my-api-tool.zip
└── manifest.json
```

仅 manifest，无需附带其他文件。

### 2.2 manifest 示例

```json
{
  "name": "天气查询",
  "typ": "api",
  "description": "查询指定城市的天气",
  "desc": "基于 OpenWeather 提供的 REST 接口",
  "industry": "通用",
  "config": {
    "schema": "<OpenAPI / Swagger JSON 字符串或对象>",
    "credentials": {
      "auth_type": "api_key",
      "api_key_header_prefix": "Bearer",
      "api_key_value": "YOUR_API_KEY"
    }
  }
}
```

### 2.3 `config` 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `schema` | 是 | OpenAPI / Swagger 文档，可以是 JSON 字符串，也可以是 JSON 对象 |
| `credentials` | 否 | 鉴权配置，结构由 `auth_type` 决定 |

> `schema` 必须是合法的 OpenAPI 文档，且 `paths` 中至少包含一个接口定义，否则解析会失败。

---

## 3. MCP 工具（`typ: mcp`）

连接一个已部署的 MCP Server，平台通过 MCP 协议调用其子工具。

### 3.1 文件结构

```
my-mcp-tool.zip
└── manifest.json
```

仅 manifest，无需附带其他文件。

### 3.2 manifest 示例

```json
{
  "name": "文件检索",
  "typ": "mcp",
  "description": "基于 MCP 协议的文件检索工具",
  "industry": "通用",
  "config": {
    "server_url": "https://mcp.example.com/sse",
    "header": {
      "Authorization": "Bearer TOKEN"
    }
  }
}
```

### 3.3 `config` 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `server_url` | 是 | MCP Server 地址 |
| `header` | 否 | 调用 MCP Server 时携带的 HTTP Header，对象类型 |

---

## 4. MCP 脚本工具（`typ: mcp_script`）

上传一段自定义 MCP 脚本（通常是 Python 脚本），平台在实例运行时通过 `cmd` 命令把脚本启动为一个本地 MCP 服务，再按 MCP 协议调用其中的子工具。脚本以 ZIP 形式提供。

### 4.1 文件结构

```
my-script-tool.zip
├── manifest.json
└── script.zip              ← 脚本包 ZIP，内含 MCP 脚本文件
```

- 根目录下**恰好一个** `.zip` 文件作为脚本包
- manifest 自身是 `.json`，不会与脚本包冲突
- 出现多个 `.zip` 会报错，请仅保留一个

### 4.2 脚本包 ZIP 内部要求

脚本包 ZIP 内是一个完整的 MCP 脚本工程，至少包含：

| 文件 | 必填 | 说明 |
|---|---|---|
| MCP 脚本入口文件 | 是 | 由 `config.cmd` 指定启动命令，例如 `main.py` |
| `requirements.txt` | 建议 | Python 依赖声明，平台会据此安装依赖 |

> 平台实例启动时，会执行 `config.cmd`（如 `python main.py`）把脚本拉起为一个本地 MCP 服务，再通过 MCP 协议与该服务通信。因此脚本入口文件路径需与 `cmd` 中的命令对应。

### 4.2 manifest 示例

```json
{
  "name": "自定义脚本工具",
  "typ": "mcp_script",
  "description": "用户上传的 Python MCP 脚本",
  "industry": "通用",
  "config": {
    "cmd": "python main.py",
    "file_name": "script.zip"
  }
}
```

### 4.3 `config` 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `cmd` | 是 | 启动脚本的命令，例如 `python main.py` |
| `file_name` | 否 | 脚本包文件名，导入时由平台自动覆盖 |
| `filemark` | 否 | 平台内部内容寻址标识，导入时自动生成，无需填写 |

> `filemark` 与 `file_name` 在导入时由平台根据附带的脚本包 ZIP 自动生成并覆盖，作者无需准确填写。

### 4.4 脚本包 ZIP 的要求

- 必须是合法的 `.zip` 文件
- 内含一个完整的 MCP 脚本工程，至少包含一个可被 `cmd` 启动的脚本入口文件
- 建议包含 `requirements.txt`（Python 依赖声明）
- 入口脚本路径需与 `config.cmd` 中的命令对应

---

## 5. 三种类型对比

| 维度 | API 工具 | MCP 工具 | MCP 脚本工具 |
|---|---|---|---|
| `typ` | `api` | `mcp` | `mcp_script` |
| 附带文件 | 无 | 无 | 一个脚本包 ZIP |
| `config` 核心字段 | `schema` / `credentials` | `server_url` / `header` | `cmd` / `file_name` |
| 运行方式 | 平台按 schema 调用远端 HTTP | 平台连接远端 MCP Server | 平台实例通过 `cmd` 启动脚本为本地 MCP 服务，再按 MCP 协议调用 |
| 适合场景 | 已有 HTTP API | 已部署 MCP Server | 自定义逻辑需本地执行 |

## 6. 打包流程

1. 按 §2 / §3 / §4 准备 `manifest.json`，填好 `name` / `typ` / `industry` / `config`
2. （仅 `mcp_script`）准备脚本包 ZIP
3. 把 manifest JSON（和脚本包 ZIP）放到一个目录的根目录下
4. 在该目录内打包成外层 ZIP，确保 manifest 在 ZIP 根目录
5. 上传外层 ZIP 到平台

### 6.1 打包命令示例

```bash
mkdir my-tool-pkg
cp manifest.json my-tool-pkg/
cp script.zip my-tool-pkg/      # 仅 mcp_script 需要

cd my-tool-pkg
zip -r ../my-tool.zip .
cd ..
```

### 6.2 验证打包结果

```bash
unzip -l my-tool.zip
```

输出里 `manifest.json` 应直接出现在第一层，而不是 `my-tool-pkg/manifest.json`。如果看到多了一层目录，说明打包方式不对，需要进入目录内再打包。

## 7. 常见错误

| 错误提示 | 原因 | 解决方法 |
|---|---|---|
| `不支持的文件格式，仅支持 .zip 文件` | 上传的不是 `.zip` | 重新打包为 ZIP |
| `文件大小超出限制，最大 200MB` | 超过 200 MB | 精简包内容 |
| `无效的 zip 文件` | ZIP 结构损坏 | 重新打包 |
| `交换包缺少 manifest json 文件` | ZIP 根目录没有 `.json` 文件 | 在根目录加入 manifest JSON |
| `manifest json 文件存在多个候选，请仅保留一个` | 根目录有多个 `.json` | 删除多余 JSON，仅保留一个 manifest |
| `name/typ/industry 字段不能为空` | manifest 缺少必填字段 | 补上 `name` / `typ` / `industry` |
| `typ must be api, mcp or mcp_script` | `typ` 值非法 | 改为 `api` / `mcp` / `mcp_script` 之一 |
| `mcp_script 交换包缺少 package zip 文件` | `mcp_script` 类型但根目录无脚本包 ZIP | 附上脚本包 ZIP |
| `mcp_script 附带多个 zip 文件，请仅保留一个脚本包` | 根目录有多个 `.zip` | 仅保留一个脚本包 |

---

## 8. 提交前自检清单

- [ ] 外层文件是 `.zip` 格式，大小 ≤ 200 MB
- [ ] ZIP 根目录下恰好有一个 `.json` 文件作为 manifest
- [ ] manifest 是 UTF-8 编码的 JSON 对象
- [ ] manifest 含 `name` / `typ` / `industry`，且均非空
- [ ] `typ` 为 `api` / `mcp` / `mcp_script` 之一
- [ ] `config` 字段与本类型要求一致（API：`schema`；MCP：`server_url`；MCP 脚本：`cmd`）
- [ ] `mcp_script` 类型在根目录附带了恰好一个脚本包 ZIP
- [ ] 用 `unzip -l` 检查，manifest 直接位于 ZIP 根目录，未多套一层目录
