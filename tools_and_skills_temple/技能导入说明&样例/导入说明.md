# SKILL 编写规范

本规范用于指导技能（Skill）作者编写符合平台解析规则的 `SKILL.md` 文件并组织 ZIP 包结构。按本规范编写的技能可被平台正确解析、导入与展示。

---

## 1. 总览

一个技能由一个 **ZIP 压缩包** 承载，包内必须包含至少一个 `SKILL.md` 文件，作为技能的入口与元数据声明。除此之外可包含正文引用的辅助文件（参考文档、模板、示例等）。

平台处理流程：

1. 接收 `.zip` 文件 → 解压
2. 在解压目录中查找 `SKILL.md`（大小写不敏感，存在多个时取目录层级最浅的一个）
3. 解析 `SKILL.md` 顶部的 YAML frontmatter，提取 `name` / `description` / `version`
4. 校验字段合法性，将元数据落库，文件落盘

任一步骤失败都会导致导入失败并返回中文错误提示。

---

## 2. ZIP 包结构

### 2.1 必备要求

| 项 | 要求 |
|---|---|
| 文件格式 | 必须为 `.zip` |
| 文件大小 | 默认上限 100 MB（可由平台侧调整） |
| 编码 | 文本类文件（含 `SKILL.md`）使用 **UTF-8** 编码 |
| 入口文件 | 至少包含一个 `SKILL.md`，建议放在 ZIP 根目录 |
| 多 `SKILL.md` | 允许存在多个，但会取目录层级最浅的一个作为入口；为避免歧义，**建议仅保留一个** |

### 2.2 推荐目录结构

```
my-skill.zip
├── SKILL.md                        ← 入口文件，必备
├── references/                     ← 辅助文档（可选）
│   ├── workflow.md
│   └── examples.md
├── templates/                      ← 模板（可选）
│   └── output.md
└── README.md                       ← 给人看的说明（可选）
```

### 2.3 自动忽略项

以下目录与文件在导入时会自动跳过，无需手动清理：

- 目录：`__MACOSX/`、`__pycache__/`、`node_modules/`、以 `.` 开头的隐藏目录
- 文件：`Thumbs.db`、`desktop.ini`、`.DS_Store`、以 `.` 开头的隐藏文件
- 二进制文件（按扩展名识别）：图片 / 音视频 / 压缩包 / 可执行文件 / Office 文档 / 字体等不会出现在编辑器目录树中，但**仍会随包导入并占用存储**

> 注：平台不会执行包内任何脚本，仅作为文本/资源文件存储与展示。

## 3. SKILL.md 文件结构

`SKILL.md` 由两部分组成：

```
---
<YAML frontmatter>
---

<Markdown 正文>
```

- **frontmatter**：用三横线 `---` 包裹的 YAML 块，声明技能元数据。必须位于文件**最开头**。
- **正文**：标准 Markdown，描述技能的行为、使用方式、参考文件索引等。

### 3.1 最小可用示例

```markdown
---
name: 我的技能
description: 一句话说明这个技能做什么。
version: 1.0.0
---

# 我的技能

正文从这里开始。
```

---

## 4. frontmatter 字段规范

### 4.1 字段一览

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `name` | 是 | string | 技能名称，见 §4.2 命名规则 |
| `description` | 是 | string | 技能描述，见 §4.3 写法规则 |
| `version` | 否 | string | 版本号，见 §4.4 版本号规则，缺省视为 `1.0.0` |
| `license` | 否 | string | 许可证声明，原样保留，不影响解析 |

> 平台对 `name` / `description` / `version` 三个字段做强校验；其他字段（如 `license`、`author` 等）原样保留，不做处理。

### 4.2 `name` 命名规则

- 非空字符串，前后空白会被自动 trim
- **禁止包含**以下字符：`/  \  :  *  ?  "  <  >  |`
- 建议长度 ≤ 64 字符
- 建议使用「中文名-英文短标识」形式，例如 `短剧编剧-short-drama-writer`

**合法示例：**

```yaml
name: 短剧编剧-short-drama-writer
name: 数据分析助手
```

**非法示例：**

```yaml
name: a/b/c              # 含 /
name: "技能: 进阶版"      # 含 :
name: 技能?              # 含 ?
```

### 4.3 `description` 写法规则（重点）

`description` 是 frontmatter 中**最容易写错**的字段。下面给出三种推荐写法与若干错误写法。

#### ✅ 推荐写法一：单行 plain scalar（最简单）

```yaml
description: 一句话说明这个技能做什么。
```

如果描述较长，单行直接写完即可，YAML plain scalar 支持任意长度。

#### ✅ 推荐写法二：双引号包裹

```yaml
description: "一句话说明这个技能做什么，可以包含英文冒号: 像这样"
```

引号包裹的字符串里可以自由使用 `:` `>` `|` 等字符，不会触发 YAML 解析歧义。适合描述里需要包含特殊字符的场景。

#### ✅ 推荐写法三：多行块标量（`>` 或 `|`）

`>` 折叠换行为空格，`|` 保留换行。**块标量指示符必须独占行尾，正文从下一行开始并缩进 2 个空格**：

```yaml
description: >
  这是一段较长的描述。
  第二行会被折叠成一个空格连接到第一行后面。
  可以写很多内容，只要保持缩进即可。
```

```yaml
description: |
  第一行
  第二行
  换行会被保留。
```

#### ❌ 错误写法一：`>` 后同行跟文字（**最常见的报错**）

```yaml
description: > 短剧编剧大师（Short Drama Screenwriting Master）...
```

YAML 规范中 `>` 是块标量指示符，**必须独占行尾**。同行跟文字会报：

> expected a comment or a line break, but found '短'

**修法**：去掉 `>`（变成 plain scalar）即可；若坚持用 `>`，按推荐写法三改成多行。

#### ❌ 错误写法二：值中含英文冒号 + 空格

```yaml
description: 触发场景: 用户提到小说改编时介入
```

YAML 会把 `触发场景:` 当成新的键，导致解析失败或值被截断。

**修法**（任选其一）：

- 把英文冒号 `:` 改成中文全角冒号 `：`：
  ```yaml
  description: 触发场景：用户提到小说改编时介入
  ```
- 用双引号包裹整个值：
  ```yaml
  description: "触发场景: 用户提到小说改编时介入"
  ```
- 用多行块标量：
  ```yaml
  description: >
    触发场景: 用户提到小说改编时介入
  ```

> 平台对未加引号、且未使用 `>` / `|` 的 `description` 行做了一层容错：会把值中的英文冒号自动替换为中文冒号再交给 YAML 解析。**但 URL 里的英文冒号也会被无差别替换**（`https://` → `https：//`），导致 URL 失效。因此**推荐主动用双引号或块标量**，不要依赖容错。

#### ❌ 错误写法三：值以特殊字符开头

```yaml
description: >这是描述       # 误把 > 当普通字符
description: *这是描述        # * 在 YAML 里是别名引用
description: &这是描述        # & 在 YAML 里是锚点
description: # 空值
```

**修法**：用双引号包裹：

```yaml
description: ">这是描述"
```

### 4.4 `version` 版本号规则

- 格式：`X.Y.Z`，三段非负整数，用英文句点 `.` 分隔
- 每段建议 0–9 单数字（平台自动递增版本时按「末位 +1，满 9 进位」处理）
- 缺省时视为 `1.0.0`

**合法示例：** `1.0.0`、`1.2.3`、`2.0.0`

**非法示例：** `v1.0.0`（带前缀）、`1.0`（段数不足）、`1.0.0.0`（段数过多）、`1.0.beta`（非整数）

> 平台在「另存为新版本」时会自动递增版本号；导入新技能时版本固定为 `1.0.0`，frontmatter 中的 `version` 字段会被覆盖。

## 5. 正文（Markdown body）

frontmatter 闭合 `---` 之后的全部内容视为 Markdown 正文，无格式限制。建议结构：

```markdown
# 技能标题

> 一句话核心理念

## 快速启动

简述触发条件与主要工作流入口。

## 核心规则

按主题分节展开。

## 参考文件索引

| 文件 | 内容 | 何时读取 |
|---|---|---|
| references/workflow.md | 详细工作流 | 使用 /xxx 时 |
```

### 5.1 引用辅助文件

正文里可通过相对路径引用 ZIP 包内其他文件，例如：

> 详细工作流见 `references/workflow.md`。

平台不会校验引用路径是否存在，但会作为提示给到调用方。

## 6. 常见错误与排查

下表给出平台返回的错误提示与对应的根因和修法。

| 错误提示 | 根因 | 修法 |
|---|---|---|
| `SKILL.md 格式不合法，缺少 frontmatter` | 文件未以 `---\n` 开头 | 在文件最开头加上 `---` 并补全 frontmatter |
| `SKILL.md 格式不合法，缺少闭合 ---` | frontmatter 没有第二个 `---` 闭合 | 在 frontmatter 末尾补一行 `---` |
| `SKILL.md 格式不合法，frontmatter 内容为空` | 两个 `---` 之间没有内容 | 补上 `name` / `description` 等字段 |
| `SKILL.md 格式不合法，无法解析` | YAML 语法错误（如 §4.3 列出的错误写法） | 按 §4.3 推荐写法修正 `description` |
| `SKILL.md 格式不合法，缺少 name 字段` | frontmatter 没有 `name`，或 `name` 为空 | 补上 `name: <技能名>` |
| `SKILL.md 格式不合法，缺少 description 字段` | frontmatter 没有 `description` | 补上 `description: <描述>` |
| `技能名称不能为空` / `技能描述不能为空` | 解析得到空值 | 同上 |
| `技能名称不能包含特殊字符: / \ : * ? " < > \|` | `name` 含非法字符 | 改名，去掉这些字符 |
| `版本号格式不合法: <version>` | `version` 不是 `X.Y.Z` 三段整数 | 改为 `1.0.0` 格式 |
| `不支持的文件格式，仅支持 .zip 文件` | 上传的不是 `.zip` | 重新打包为 ZIP |
| `文件大小超出限制，最大 100MB` | 超过大小上限 | 精简包内大文件 |
| `压缩包结构不合法，缺少 SKILL.md 文件` | ZIP 内没有 `SKILL.md` | 在包根目录加入 `SKILL.md` |

## 7. 完整示例

### 7.1 简单技能

`SKILL.md`：

```markdown
---
name: 周报生成器
description: 根据本周 Git 提交记录生成结构化周报。
version: 1.0.0
---

# 周报生成器

## 触发场景

用户请求「写周报」「总结本周工作」时触发。

## 输出格式

1. 本周完成事项
2. 下周计划
3. 风险与阻塞
```

ZIP 结构：

```
weekly-report.zip
└── SKILL.md
```

### 7.2 含辅助文件的技能

`SKILL.md`：

```markdown
---
name: 短剧编剧-short-drama-writer
description: "短剧编剧大师——专精小说/IP改编为短剧、国内外爆款市场分析的专业编剧技能。"
version: 1.0.0
license: Proprietary
---

# 短剧编剧

## 快速启动

- 有小说/IP素材，要改短剧？→ 读取 `references/novel-adaptation.md`
- 想了解市场/选题？→ 读取 `references/market-intelligence.md`

## 参考文件索引

| 文件 | 内容 |
|---|---|
| references/novel-adaptation.md | 小说改编方法论 |
| references/market-intelligence.md | 市场数据与赛道分析 |
```

ZIP 结构：

```
short-drama-writer.zip
├── SKILL.md
└── references/
    ├── novel-adaptation.md
    └── market-intelligence.md
```

## 8. 自检清单

提交前请逐项确认：

- [ ] ZIP 内至少有一个 `SKILL.md`，建议仅一个，放在根目录
- [ ] `SKILL.md` 以 `---\n` 开头，且 frontmatter 有闭合 `---`
- [ ] frontmatter 含 `name` 和 `description`，且非空
- [ ] `name` 不含 `/ \ : * ? " < > |`
- [ ] `description` 未使用 `> 文字` / `| 文字` 这种同行块标量错误写法
- [ ] 若 `description` 值含英文冒号、`>`、`|`、`*`、`&` 等特殊字符，已用双引号包裹或改用多行块标量
- [ ] `version`（如有）为 `X.Y.Z` 三段整数格式
- [ ] `SKILL.md` 与所有文本文件均为 UTF-8 编码
- [ ] ZIP 大小 ≤ 100 MB
